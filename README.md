# Nautilus Sonar

## Overview

Nautilus Sonar is a passive network monitoring and detection platform.

The project currently provides:

* Centralized rule management through Laravel
* Suricata rule distribution
* Passive event collection
* Event normalization
* Event indexing into OpenSearch
* Aggregation-based incident generation
* Correlation-based incident generation

# Components

## Laravel Backend

Provides centralized management of detection rules.

Currently supported rule types:

* Suricata
* Aggregation
* Correlation

The backend is the single source of truth for rules.

---

## Nautilus Sonar

Responsible for:

* Reading Suricata EVE events
* Normalizing events
* Publishing events to ValKey

Nautilus Sonar does not generate incidents.

---

## Nautilus Consumer

Responsible for:

* Reading events from ValKey
* Indexing events into OpenSearch

Target index:

```text
nautilus-events
```

---

## Nautilus Detection Engine

Current implementation:

```text
nautilus-correlator
```

Responsibilities:

* Download centralized rules from Laravel
* Execute aggregation rules
* Execute correlation rules
* Create incidents
* Index incidents into OpenSearch

Target index:

```text
nautilus-incidents
```

# Rule Types

## Suricata Rule

Example:

```text
alert udp any any -> any 53 (
    msg:"NAUTILUS TEST - ANY DNS UDP 53";
    sid:1000003;
    rev:1;
)
```

This rule generates an alert whenever UDP traffic is detected towards destination port 53.

---

## Aggregation Rule

Purpose:

Generate an incident when multiple occurrences of the same event are detected within a time window.

Example:

```text
Event:
Suricata Alert SID 1000003

Threshold:
2 events

Window:
300 seconds

Result:
Incident generated
```

Tested and verified.

---

## Correlation Rule

Purpose:

Generate an incident when multiple different conditions are detected within a time window.

Example:

```text
Condition 1:
Alert SID 1000003

AND

Condition 2:
DNS Event

Window:
300 seconds

Result:
Incident generated
```

Tested and verified.

# Incident Structure

Current incident format:

```json
{
  "incident_id": "uuid",
  "correlation_key": "correlation-key",
  "rule_id": "rule-id",
  "rule_uuid": "rule-uuid",
  "rule_name": "rule-name",
  "incident_type": "incident-type",
  "severity": "medium",
  "description": "description",
  "evidence": {}
}
```

## incident_id

Stable UUID generated from the correlation key.

Example:

```text
9a9db256-4bb1-501a-9e47-ea3a41e09d18
```

## correlation_key

Human-readable identifier used for deduplication.

Example:

```text
dns-alert-plus-dns-event-correlation-1781097300
```

This value is currently used as the OpenSearch document _id.
